## 2026-11-27 · 화면 기능 실제 실행: Stage 2 끝
- Claude로 「로그인 화면」의 작업 7개를 끝냈습니다(각본 PO). 시나리오 17개가 Android 가상 기기와 웹에서 모두 통과했고, 화면 비교도 모두 허용 비율 안에 들었습니다. 맞는 화면은 0.5~2.3%, 어긋난 화면은 5.6% 이상으로 갈려 허용 5%를 그대로 둡니다.
- 어긋난 화면 두 번은 모두 Android 글꼴 여백 탓이었고, 구현 노드가 부품 코드를 고쳐 한 번에 맞췄습니다. 그 뒤 화면은 첫 차례에 맞았습니다.
- 개발자가 8번 개입했고, 모두 하네스나 시험 환경 문제였습니다. 고친 것: 시간 제한을 플로우 파일 수에 맞춤, 승인된 설계를 지시문보다 앞세움, 리뷰가 「단위 테스트만 없음」을 고름, 사람이 이어 갈 노드를 정하는 `approve --to`, 단위 테스트의 react-native 위치, Maestro 드라이버 재시도.
- **측정 바로잡음:** 이어 쓴 Claude 세션의 금액을 차례마다 누적값으로 적고 있었습니다. 이제 차례 몫만 적고, 보고서는 예전 원장도 풀어 셉니다. 다시 센 값은 조각 2 오너 실행 약 $7.8(처음 $27.2), 조각 2 Claude 실행 약 $9.3(처음 $27), 이번 실행 전체 약 $35입니다. 조각 1의 값($6.18 등)도 누적을 더한 값이라 실제보다 큽니다(원장이 없어 다시 세지 못함).
- 개선 후보: 화면 작업의 N24 관문에 웹 플로우 더하기, N00F가 Android 글꼴 여백을 미리 처리하기.

## 2026-11-27 · 화면 기능 실제 실행: 다시 그리기, Stage 1, Stage 2 시작
- 각본 PO가 물을 것에 답한 뒤 Stage 0을 다시 돌렸습니다. 와이어프레임과 완성 화면만 다시 그렸고, 리뷰가 잘못 그린 프레임 하나를 잡아 되돌렸습니다. 다시 그리기에 약 $2.4가 들었습니다(처음엔 누적 금액을 더해 $15.7로 적음). Stage 1은 작업 7개를 약 $1.4에 만들었습니다.
- Stage 2를 Claude로 돌리기 시작했습니다. 가상 기기는 18초에 떴고, 첫 작업(서버 시험 경로)은 리뷰가 빠진 구현을 잡아 되돌린 뒤 끝났습니다.
- 실제 실행에서 찾아 고친 하네스 문제: 리뷰 지적이 영어로 나옴, 결과가 여러 번 나오는 시나리오의 프레임, 구현 노드가 설계한 앱 폴더를 못 고침(`writes`에 빼기 패턴), Stage 2가 기준 화면과 플로우 쓰는 법을 모름(맥락 「화면 작업」), 테마가 `mobile/` 밖의 토큰을 써 앱 빌드가 깨짐(번들러 설정, N00F가 앱을 빌드해 봄, N22에서 빌드가 깨지면 바로 사람에게), Playwright 실패 기록이 커밋에 섞임.
- 보고서에 화면 칸을 더했습니다: N26F 첫 통과율, 화면 차이 비율 분포, 디자인 되돌림, 노드별 Figma 호출 수, 기기·빌드·플로우 시간. Codex 세션은 등록된 다른 MCP 서버를 끄고 Figma 노드에만 Figma 서버를 엽니다. 하네스 테스트는 242개입니다.
- 첫 화면 비교 결과: 웹은 입력칸이 Figma보다 조금 높아 5.65%·5.89%로 허용 5%를 살짝 넘었고, Android는 13.8%였습니다. 원인은 디자인 시스템 부품(입력칸)의 플랫폼 기본 여백입니다. 오너 결정으로 구현 노드가 부품 코드를 Figma대로 그려지게 고칠 수 있게 했습니다(값·글꼴·Figma는 그대로 잠금).
- 찾아 고친 것: Android 플로우가 키보드 없이 `hideKeyboard`를 불러 앱이 닫힌 채 홈 화면이 찍혔습니다(지시문 실수). 이제 글자를 넣었을 때만 키보드를 내리고, 화면 비교에서 찍은 화면이 앱이 아니면 분류가 플로우(N22)로 보냅니다.
- **바뀐 노드:** N00F, N03F, N22, N24, N25, N26F, N27

## 2026-11-27 · 조각 3 명세의 제안 승인
- 조각 3 명세가 제안한 일곱 가지(기능마다 작업 유형, N04 승인 때 Figma 버전으로 프레임 고정, Figma 쓰기 도구는 디자인 노드에만, 하네스가 직접 하는 화면 비교, 최소 디자인 시스템과 같은 글꼴, 시나리오마다 끝 화면 프레임, Stage 2에 한 번 띄우는 가상 기기)를 오너가 그대로 승인했습니다. 구현 1단계(시험 프로젝트 `login-app`, 로컬 빌드, 가상 기기, 인수 테스트 연기 시험)를 마쳤습니다. 가상 기기 30초, Android release 빌드 3분 20초(캐시), Maestro 흐름 7초, 웹 내보내기 7초, Playwright 1.2초입니다. 같은 글자가 Android와 웹에서 다른 글꼴로 찍혀, 같은 글꼴 파일을 쓰는 이유가 보였습니다.
- 구현 2단계를 마쳤습니다: 기능마다 작업 유형(`4dd story --type`), 화면 기능의 플랫폼별 관문(Android 빌드·플로우, 웹 내보내기·Playwright), 디자인 노드(N00F·N03W·N03F)와 관문 넷. 하네스 테스트는 217개입니다.

- 화면 기능의 Stage 0을 Claude로 실제로 돌렸습니다(각본 PO). 디자인 시스템, 와이어프레임(리뷰가 빠진 상태를 잡아 한 번 되돌림), 완성 화면 7장을 Figma에 그리고, 검토 페이지에 화면 이미지와 디자인 시스템이 들어갔습니다. 표시 가격 약 $3.5입니다(처음엔 누적 금액을 더해 $11로 적음). 물을 것이 남은 채 화면을 그리던 것은 고쳐, 이제 N04에서 먼저 묻습니다. Code Connect는 Figma의 Organization 이상 요금제에서만 되어, 오너 결정으로 저장소 짝 파일로 갑니다.
- 오너가 정한 일하는 방식: 결정이 필요한 질문은 휴대폰 알림이 가도록 질문 창(AskUserQuestion)으로 묻습니다.

## 2026-11-26 · 오너가 PO인 실제 실행: 「회원 가입」을 끝까지
