## 2026-11-25 · 하네스 구현 3단계: 잠금 검사와 훅
- 쓰기 잠금 규칙을 `harness/src/lock.ts` 한 곳에 두었습니다. 세션은 그 노드의 `writes`만 고칠 수 있고, `.4dd/`는 하네스만 씁니다. Claude 훅, Codex 훅, git pre-commit, 차례 뒤 변경 검사가 모두 이 규칙을 부릅니다.
- `4dd check hook`이 두 도구의 훅 입력(Claude 편집 도구의 `file_path`, Codex `apply_patch`의 패치 머리, 셸 명령)을 읽어 막거나 통과시키고 원장에 남깁니다. 기록과 브랜치를 바꾸는 git 명령은 하네스만 합니다.
- `4dd check diff`가 차례 뒤 바뀐 파일을 보고 노드에서 고칠 수 없는 곳을 되돌립니다. `.4dd/`에서는 원장과 `state.json`만 바뀌어도 되므로, 셸로 훅 설정을 고쳐도 걸립니다. 원장이 덧붙기만 했는지도 따로 봅니다.
- `4dd check commit`(git pre-commit): 하네스의 커밋은 그 노드의 `writes`와 원장만, 사람의 커밋은 잠긴 파일을 막습니다. 일부러 풀고 커밋해도 기준 해시와 달라 다음 노드에서 걸립니다.
- `4dd init`이 시험 프로젝트를 새 git 저장소로 만들고, Claude·Codex·git 훅을 걸고, 잠긴 파일의 기준 해시를 고정합니다.
- 실제 Claude와 Codex 세션으로 훅이 막히는지는 5단계(어댑터)에서 확인합니다. 지금은 두 도구의 훅 입력 형식으로 시험했습니다.

## 2026-11-25 · 하네스 구현 2단계: 노드 정의, 원장, 상태
- `harness/nodes/nodes.yaml`에 Stage 2 노드 아홉 개(N21~N29)를 정의하고, 작업 세션과 리뷰 세션이 받을 노드 지시문 다섯 개(N22~N25, N27)를 썼습니다.
- 노드 정의를 읽을 때 형식을 검사합니다: 통제 어휘에 없는 실패 원인, 없는 노드로 가는 경로, 승인 뒤 갈 곳이 없는 사람 경로, 지시문이 없는 세션 노드 등을 모두 모아 알립니다.
- 원장(`.4dd/events.jsonl`) 이벤트 9종의 형식을 정해 쓰고 읽습니다. 형식이 틀린 이벤트는 쓰지 않고, 쓰다 끊긴 마지막 줄은 주의만 남깁니다.
- `state.json`을 원장에서 다시 만듭니다. 원장이 더 길거나 파일이 깨졌으면 다시 만들어서, 중간에 죽어도 그 자리부터 이어 갈 수 있습니다. 사람이 승인하거나 힌트를 주면 그 노드와 작업의 횟수를 새로 줍니다.
- `4dd status`로 지금 작업, 노드, 되돌림 수, 기다리는 이유를 봅니다.
- 명세의 `nodes.yaml` 형식을 실제 파일에 맞췄습니다: 관문의 통과 조건을 `expect: pass | fail`로 쓰고, 추가 검사는 `checks`로 붙입니다.

- 예시 템플릿(`spec.md`, `.feature`, `tasks.md`)에 추적 ID(`R`, `@S`, `T`)를 붙였습니다. 설계 ③과 어긋나 있었습니다.

## 2026-11-25 · 하네스 실행을 다루는 자기 개선용 온톨로지
- 하네스 설계 ③의 온톨로지가 개발 산출물(요구사항, 시나리오, 작업, 테스트, 커밋)만 다루고, 하네스가 어떻게 돌았는지는 다루지 않았습니다. 오너 요청으로 스프린트 루프의 자기 개선용 온톨로지로 고쳐 쓰고, 하네스 실행을 중심에 두었습니다.
- 하네스 실행 타입을 더했습니다: 노드 실행, 훅 실행, 지시문, 스킬, 훅, 사람 개입, 하네스 버전. 관문 실행 기록과 학습 항목도 이 묶음으로 옮겼습니다. 관계(`loaded`, `blocked`·`allowed`, `intervened_in`, `ran_on` 등)는 주체, 관계, 대상 표로 적었습니다.
- 원장에 노드 실행과 훅 실행을 남기는 형식을 정했습니다. 내용은 남기지 않고 ID, 해시, 숫자만 남기며, `loaded`에는 하네스가 `4dd context`로 넘겨준 지시문과 스킬을 적습니다.
- 회고에서 돌릴 질의 일곱 가지로 반복 실수와 비효율을 찾습니다: 같은 훅에 반복해서 막힘, 같은 실패 원인 반복, 두 노드 사이 왕복, 효과 없는 스킬과 지시문, 규칙 효과, 사람 개입이 몰리는 곳, 도구별 차이. 찾은 것은 개선 후보가 되어 시험 세트를 거친 뒤에만 규칙이 됩니다.
- 첫 구현 범위(MVP)에 노드 실행, 훅 실행, `4dd context`가 넘겨준 목록을 더했습니다. 빈 곳 G20을 더했습니다.

- 오너가 노드 맵 시안을 아직 정하지 않았습니다. 정할 때까지 아티팩트의 노드 맵을 Mermaid 대신 시안 B(위에서 아래로 흐르는 지하철 노선도형)로 임시로 그립니다. 처음에는 "오너가 고른 시안 B"라고 잘못 적었다가 바로잡았습니다.
- 스테이지 구역이나 버튼을 누르면 그 스테이지가 넓어지고 이름과 갈 곳이 자세히 보입니다.
- 병렬로 진행되는 것을 따로 그립니다: 반복 노드 N2D와 프로젝트당 1회 노드 N00F는 본선 옆 지선, 수시로 하는 Stage 0은 회색 수시 노선입니다.
- 그림 데이터는 그대로 `docs/workflow.md` 노드 맵에서 만들어지고, 그리는 코드는 `docs-view/metro.js`에 있습니다.

## 2026-11-18 · 노드 맵 스테이지 순서 바로잡기
- 노드 맵이 Stage 4 → 1 → 2 → 3 → 0 순으로 뒤섞여 그려지던 문제를 고쳤습니다. 이제 왼쪽부터 Stage 0 → 4 순서이고, 각 스테이지 안에서는 위에서 아래로 진행합니다.
- 원인은 앞 스테이지로 거꾸로 가는 긴 화살표였습니다. 이런 되돌림은 화살표 대신 점선 상자 `↩ N02` 같은 표지로 그립니다.
- 검사를 추가했습니다: 노드 맵에 앞 스테이지로 거꾸로 가는 화살표가 생기거나, `workflow.md`와 사이트의 노드 맵이 서로 다르면 빌드와 검사가 실패합니다.
