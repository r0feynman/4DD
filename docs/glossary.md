# 4DD 용어집

## 구조 용어

| 용어 | 정의 | 예 |
|---|---|---|
| **스프린트** | 4DD를 한 바퀴 도는 1~4주 기간. Stage 0~4로 이루어진다. | 2주 스프린트 |
| **스테이지(Stage)** | 스프린트 한 바퀴를 나눈 다섯 구간. 노드 여러 개를 묶고 0 → 4 순서로 진행한다. | Stage 1 스프린트 플래닝 = N11~N15 |
| **노드(Node)** | 스테이지 안의 단계 하나. 고유 ID가 있고, 하나의 방법론에 속하며, 끝나면 다음 노드로 넘어가는 최소 단위. | N26F |
| **작업 노드** | 무언가를 만들거나 수행하고 산출물을 남기는 노드. | N02 `spec.md` 작성 |
| **판단 노드** (◇) | 예/아니오로 다음 노드를 정하는 노드. | N28 DoD 충족? |
| **반복 노드** | 순서와 상관없이 정해진 주기로 반복되는 노드. | N2D 데일리 스크럼 |
| **경로(Path)** | 노드에서 노드로 가는 연결. | N26 → N26F |
| **되돌림(Loop-back)** | 판단 노드가 "아니오"일 때 앞 노드로 돌아가는 경로. | N28 아니오 → N23 |
| **루프(Loop)** | 여러 노드가 반복되는 구간. | TDD 루프 = N23 → N24 → N25 |

## 노드 ID 규칙

```
N  2  6  F
│  │  │  └ 접미사: F = Figma 노드 (없으면 일반 노드)
│  │  └── 스테이지 안에서의 순서 (반복 노드는 D)
│  └───── 스테이지 번호 (0 백로그 정리 ~ 4 회고)
└──────── Node
```

## 스테이지

| 스테이지 | 이름 | 노드 | 스크럼 공식 이벤트? |
|---|---|---|---|
| 0 | 백로그 정리 | N01~N04 | ✗ (수시로 하는 활동) |
| 1 | 스프린트 플래닝 | N11~N15 | ✓ |
| 2 | 개발 | N21~N29, N2D | ✗ (스프린트 기간 자체) |
| 3 | 스프린트 리뷰 | N31~N33 | ✓ |
| 4 | 회고 | N41~N44 | ✓ |

데일리 스크럼은 스크럼 공식 이벤트지만 4DD에서는 스테이지가 아니라 Stage 2 안의 반복 노드(N2D)다.

## 방법론 용어

| 용어 | 정의 |
|---|---|
| **4DD** | 4 Driven Development. Spec, Behavior, Design, Test 네 가지 주도 개발을 스크럼 스프린트 안에서 함께 돌리는 개발론. |
| **SDD** (Spec-Driven) | 코드 전에 스펙 문서(`spec.md`, `design.md`, `tasks.md`)를 쓰고 그것을 기준으로 개발한다. |
| **BDD** (Behavior-Driven) | 사용자 관점의 기대 동작을 Given-When-Then 시나리오로 먼저 정의한다. |
| **Design** (Figma) | 시나리오마다 실제로 작동하는 화면 흐름을 Figma 프로토타입으로 만든다. |
| **TDD** (Test-Driven) | 실패하는 단위 테스트를 먼저 쓰고(Red), 통과시키고(Green), 정리한다(Refactor). |
| **사용자 스토리** | 사용자가 원하는 기능 하나를 짧게 적은 백로그 항목. |
| **시나리오** | 스토리의 기대 동작을 Given-When-Then으로 쓴 문장. 인수 조건이 된다. |
| **프레임** | 시나리오의 Given·Then 상태를 그린 Figma 화면 하나. |
| **인수 테스트** | 시나리오를 실제 화면에서 자동으로 확인하는 E2E 테스트. |
| **DoD** (Definition of Done) | 작업 완료 기준. 4DD에서는 네 가지를 모두 충족해야 한다 (README 참고). |
