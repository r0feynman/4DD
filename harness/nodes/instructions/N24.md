# N24 Green · 통과하게 구현

## 목표
N23에서 실패하게 만든 단위 테스트를 통과시키는 가장 작은 코드를 씁니다.

## 할 것
- 「이번 작업」의 요구사항과 `design.md`를 따릅니다. 파일 위치, 함수 이름, API 응답은 설계에 적힌 대로 씁니다.
- 실패한 테스트 출력이 있으면 그 원인부터 고칩니다.

## 화면 작업이면 (맥락에 「화면 작업」이 있을 때)
- 화면은 설계의 파일 위치(`mobile/` 아래)에 씁니다. 디자인 시스템의 부품(`mobile/ui/`)과 테마 값만 씁니다. 고정 색·간격·글자 크기를 쓰지 않습니다.
- 값(`mobile/theme.ts`, 그 원본 `design/tokens.json`)과 글꼴은 고칠 수 없습니다. 부품 코드(`mobile/ui/`)는 플랫폼에서 Figma대로 그려지게 고칠 수 있습니다(예: Android·웹 입력칸의 기본 여백을 없앰). 값은 늘 테마에서 가져오고, 부품을 고치면 그 부품을 쓰는 다른 화면도 같이 맞는지 생각합니다.
- 맥락의 기준 화면 이미지(`design/frames/<S>.png`)를 Read로 열어 보고 배치, 글자, 간격, 색을 맞춥니다. N26F가 플로우가 찍은 화면을 이 이미지와 픽셀로 비교합니다.
- testID와 보이는 글자는 이 작업의 플로우 파일(맥락에 그대로 있음)이 찾는 것과 같아야 합니다.
- 서버 주소는 `process.env.EXPO_PUBLIC_API_URL`로 씁니다(Android는 빌드 때 에뮬레이터에서 본 PC 주소, 웹은 빈 값이라 같은 출처).
- 화면 작업이면 관문이 단위 테스트에 더해 이 작업의 **웹 플로우**도 돌립니다(통과해야 함). 실패한 단위 테스트만 맞추고 화면에 잇지 않으면(버튼이 서버를 부르지 않음, 화면 분기가 없음) 여기서 막힙니다. 웹은 `npm run -s build:web && npx playwright test <웹 테스트 파일>`로 미리 돌려 볼 수 있습니다. Android 플로우와 화면 비교는 N26·N26F에서 돕니다.

## 하지 말 것
- 이 노드에서 고칠 수 있는 곳(맥락 머리) 밖을 고치지 않습니다. 테스트, 스펙, 설정, 디자인 시스템은 잠겨 있습니다.
- 테스트를 통과시키려고 테스트가 보는 값만 맞추는 코드를 쓰지 않습니다.
- 커밋하지 않습니다. 하네스가 합니다.
