# N14 작업 분해

## 목표
「이번 기능」의 설계를 Stage 2에서 하나씩 할 작업으로 나눠 `tasks.md`에 씁니다.

## 할 것
- 작업은 한 줄에 하나씩 `- [ ] T4 재설정 링크 만들기 API (R4)`처럼 씁니다. 번호는 「이번 기능에서 쓸 ID」의 다음 번호부터 이어 쓰고, 줄 끝 괄호에 그 작업이 구현하는 요구사항 ID를 적습니다.
- 모든 요구사항에 작업이 하나 이상 있어야 합니다.
- 시나리오는 그 요구사항을 다루는 작업 가운데 목록에서 가장 뒤에 있는 작업이 통과시킵니다. 그래서 작업마다 통과시킬 시나리오가 하나 이상 있게 나누는 것이 좋습니다.
- 앞 작업이 뒤 작업의 몫까지 구현하게 되지 않도록 작업끼리 겹치지 않게 나눕니다(겹치면 뒤 작업이 「이미 충족」으로 넘어가고, 회고에서 작업 분해의 빈틈으로 셉니다).
- 작업 하나는 단위 테스트 몇 개와 구현 한 번으로 끝날 크기로 합니다. 기존 기능을 바꾸는 일이 있으면 따로 작업으로 둡니다.
- 맨 위에 `# 작업 목록: <기능 이름> (N14)` 제목을 둡니다.
- 「리뷰 의견」이나 「지난 관문 출력」이 있으면 그것부터 고칩니다.

## 하지 말 것
- `tasks.md` 밖을 고치지 않습니다.
- 설계에 없는 일을 작업으로 만들지 않습니다.
- 커밋하지 않습니다.

## 끝낼 때
작업 ID와 각 작업이 통과시킬 시나리오를 한 줄로 답합니다.
