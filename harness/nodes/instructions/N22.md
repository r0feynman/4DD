# N22 인수 테스트 작성 (처음엔 실패)

## 목표
「이번 작업」의 시나리오마다 인수 테스트를 하나씩 씁니다. 아직 구현이 없으므로 돌리면 실패해야 합니다.

## 할 것
- 시나리오 ID를 파일 이름으로 씁니다: `@S1`이면 `tests/acceptance/S1.test.ts`.
- 작업이 인수 테스트의 공용 파일(`tests/e2e/`·`tests/acceptance/` 아래의 픽스처, 공용 함수)을 만들라고 하면, 맡은 시나리오가 없어도 이 노드에서 설계대로 만듭니다. 다른 노드는 `tests/`의 그 자리를 고칠 수 없습니다.
- 시나리오의 조건, 만일, 그러면을 테스트 안에서 그대로 따라갑니다. 단계를 빼거나 더하지 않습니다.
- 백엔드는 `design.md`의 API로 요청하고 응답을 확인합니다. 앱은 `buildApp`으로 만들고 서버를 띄우지 않습니다.
- 지난 관문 출력이 있으면, 무엇이 모자랐는지부터 고칩니다.

## 화면 작업이면 (맥락에 「화면 작업」이 있을 때)
- `tests/acceptance/` 대신 맥락의 표대로 플랫폼마다 한 파일을 씁니다: Android는 Maestro 플로우 `tests/e2e/android/<S>.yaml`, 웹은 Playwright `tests/e2e/web/<S>.spec.ts`. 첫 줄 주석에 시나리오 태그를 둡니다(`# @S15 @R10`, `// @S15 @R10`).
- 두 파일은 같은 시나리오를 같은 순서로 따라갑니다. 화면 요소는 설계의 testID로 찾고, 보이는 글자는 시나리오의 값 그대로 확인합니다.
- 조건(회원이 있음, 시간이 지남)을 만드는 방법은 설계(`design.md` 「인수 테스트」)가 정한 대로 합니다. 설계가 정하지 않았으면 화면을 눌러 만들지 않고 설계의 API로 만듭니다. Playwright는 `request.post`, Maestro는 `runScript`의 `http.post`입니다. Maestro의 `http.post`는 본문이 없으면 플로우가 오류로 멈추므로, 보낼 것이 없어도 `{ headers: { "Content-Type": "application/json" }, body: "{}" }`를 붙입니다(웹은 본문 없이도 되어 Android에서만 깨짐, 실제 실행). 화면 동작처럼 적힌 조건(「로그인 버튼을 5번 연속 눌렀다」)도 설계가 화면으로 하라고 하지 않았으면 API로 만듭니다. Android 입력은 한 글자씩 느려, 조건까지 화면으로 하면 플로우가 몇 분씩 걸립니다.
- Maestro 플로우는 맥락의 앱 ID로 `appId:`를 쓰고, 첫 단계에서 `- launchApp: { clearState: true }`로 앞 시나리오의 상태를 지웁니다. 서버는 플로우마다 새로 뜹니다.
- **마지막 단계에서 끝 화면을 찍습니다.** 화면 비교(N26F)가 이 이미지를 기준 화면과 비교합니다.
  - Maestro: `- takeScreenshot: S15`. 글자를 넣어 키보드가 떠 있을 때만 그 앞에 `- hideKeyboard`를 씁니다. Android에서 키보드가 없을 때 `hideKeyboard`는 뒤로 가기를 눌러 앱을 닫습니다(실제 실행에서 홈 화면이 찍힘). 찍기 바로 앞에 끝 화면의 요소를 `- assertVisible`로 한 번 더 확인합니다.
  - Playwright: 입력칸에서 포커스를 빼고(`await page.locator("body").click({ position: { x: 1, y: 1 } })` 등) `await page.screenshot({ path: ".4dd/shots/web/S15.png" })`
  - 찍기 전에 확인할 글자가 보이는지 먼저 확인합니다(화면이 다 그려진 뒤 찍도록).
- 도우미 플로우와 스크립트는 `tests/e2e/android/lib/`, `tests/e2e/web/lib/` 아래에 둡니다. 맨 위 폴더의 `.yaml`·`.spec.ts`는 모두 시나리오로 돌립니다.
- 앱 빌드는 성공해야 하고, 화면이 아직 없으므로 플로우는 실패해야 합니다. 웹은 `npm run -s build:web && npx playwright test tests/e2e/web/S15.spec.ts`로 빨리 돌려 볼 수 있습니다.

## 하지 말 것
- `tests/acceptance/`와 `tests/e2e/` 밖을 고치지 않습니다. 스펙, 시나리오, 설정, 구현 코드는 이 노드에서 잠겨 있습니다.
- 테스트를 건너뛰게 하는 표시(`skip`, `todo`, `only`)를 쓰지 않습니다.
- 커밋하지 않습니다. 하네스가 합니다.
