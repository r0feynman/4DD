# N03W 시나리오별 와이어프레임

## 목표
「이번 기능」의 화면 시나리오마다 다섯 상태(성공, 실패, 빈 상태, 로딩, 오류)를 회색 상자 와이어프레임으로 그리고, `specs/<기능>/states.md`에 정리합니다. 빠진 상태를 여기서 찾아야 개발 중에 「이럴 땐 어떤 화면?」으로 돌아오지 않습니다.

## 먼저 읽을 것
- Figma에 쓰기 전에 공식 스킬 `figma-use`를 읽습니다(`get_figma_skill`로 `skill://figma/figma-use/SKILL.md`).

## 할 것
- Figma 파일(`design/figma.json`의 `file`)의 「와이어프레임」 페이지에 시나리오마다 프레임을 그립니다. 크기는 360×800, 이름은 `S15/성공`, `S15/오류`처럼 시나리오 ID와 상태입니다. 색은 회색만, 글자는 실제 문구 대신 짧은 설명이어도 됩니다.
- 디자인 시스템의 컴포넌트(`Button`, `TextField`, `Text`, `Banner`)를 회색으로 놓아 자리만 잡습니다.
- 화면 위 32와 아래 24는 비워 둡니다(기기의 상태 표시줄과 내비게이션 막대 자리).
- `specs/<기능>/states.md`를 이렇게 씁니다. 상태가 그 시나리오에 없으면 「해당 없음: 이유」로 적습니다.
  ```
  ## S15
  - 성공: 환영 화면 (와이어 S15/성공)
  - 실패: 비밀번호 틀림 안내 띠 (와이어 S15/실패)
  - 빈 상태: 해당 없음: 입력 전 화면이 첫 화면
  - 로딩: 로그인 버튼이 눌린 채 비활성 (와이어 S15/로딩)
  - 오류: 서버에 닿지 않음 안내 띠 (와이어 S15/오류)
  ```
- 화면이 없는 시나리오(서버만 확인)는 `- 화면 없음: 이유` 한 줄만 씁니다.

## 하지 말 것
- 시나리오와 스펙을 고치지 않습니다. 시나리오에 없는 상태가 꼭 필요하면 `states.md`에 적고 끝낼 때 알립니다(PO가 N04에서 봄).
- 완성 화면(색, 실제 문구)을 그리지 않습니다. N03F가 합니다.
- 커밋하지 않습니다.

## 끝낼 때
시나리오 수와 상태 칸 수를 한 줄로 답합니다.
