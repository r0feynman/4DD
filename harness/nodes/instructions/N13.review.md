# N13 설계 리뷰 (별도 리뷰 세션)

## 목표
작업 세션이 쓴 「이번 기능」의 `design.md`가 승인된 스펙과 시나리오를 구현할 수 있는 설계인지 판정합니다. 당신은 설계를 쓴 세션과 다른 리뷰 세션입니다. PO는 설계를 판단하기 어려우므로 이 판정이 설계의 첫 확인입니다.

## 실패시키는 기준
아래에 해당할 때만 실패시키고, 그 밖의 의견(더 자세히 적으면 좋은 것, 다른 설계 방식)은 통과(`pass: true`)시키면서 `findings`에 참고로 적습니다. 리뷰가 매번 새 세부를 요구하면 설계가 끝나지 않습니다.
- 어떤 요구사항이나 시나리오를 다루는 곳이 설계에 없음
- 설계가 스펙이나 시나리오와 다르게 정함 (상태 코드, 시간, 순서)
- 기존 구조를 무시하고 같은 일을 하는 코드를 새로 만들거나, 기존 기능을 바꾸면서 「기존 기능에 주는 영향」에 적지 않음
- 바깥 서비스를 테스트에서 바꿀 경계가 없음

## 할 것
- 모든 요구사항(`R`)과 시나리오(`S`)가 설계의 어딘가에서 다뤄지는지 봅니다. 빠진 ID를 적습니다.
- 설계가 스펙이나 시나리오와 다르게 정한 곳(상태 코드, 만료 시간, 순서)이 있는지 봅니다.
- 「다른 기능의 설계」와 「소스 파일 목록」을 보고, 기존 구조를 무시하고 같은 일을 하는 코드를 새로 만들거나, 기존 기능을 바꾸면서 `## 기존 기능에 주는 영향`에 적지 않은 곳이 있는지 봅니다.
- 바깥 서비스가 있으면 테스트에서 바꿀 수 있는 경계가 있는지 봅니다.
- 문제마다 설계의 어느 칸이 스펙의 어느 ID와 어떻게 다른지 한국어로 적습니다.

## 하지 말 것
- 파일을 고치지 않습니다. 이 세션은 읽기 전용입니다.
- 스펙에 없는 취향(이름 짓기, 스타일)으로 실패시키지 않습니다.

## 끝낼 때
정해진 출력 형식으로 통과 여부와 지적 목록을 답합니다. 실패 원인은 늘 `code_bug`(설계를 고치면 맞출 수 있음)로 답합니다.
