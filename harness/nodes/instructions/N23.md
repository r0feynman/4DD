# N23 Red · 실패하는 단위 테스트 작성

## 목표
「이번 작업」을 구현하기 위해 다음에 필요한 동작 하나를 단위 테스트로 씁니다. 아직 구현이 없으므로 돌리면 실패해야 합니다.

## 할 것
- `tests/unit/`에 씁니다. 파일 이름은 테스트하는 모듈 이름을 따릅니다(예: `src/lockout.ts` → `tests/unit/lockout.test.ts`).
- 처음 들어왔을 때는 한 번에 작은 동작 하나만 테스트합니다.
- 지난 관문 출력(실패한 인수 테스트나 리뷰 지적)이 있으면, 그것을 고치는 데 필요한 테스트부터 씁니다. **지적이 여럿이면 지적마다 그것을 드러내는 실패 테스트를 이번 차례에 모두 씁니다.** 하나만 고치고 나머지를 미루면 리뷰가 다시 되돌려, 판단 노드의 횟수 제한(연속 3번)을 다 쓰게 됩니다.
- 참고로만 적힌 지적("참고, 실패 사유 아님")은 테스트하지 않아도 됩니다.

## 하지 말 것
- `tests/unit/` 밖을 고치지 않습니다. 구현 코드는 다음 노드(N24)에서 씁니다.
- 이미 있는 테스트를 지우거나 약하게 바꾸지 않습니다.
- 테스트를 건너뛰게 하는 표시(`skip`, `todo`, `only`)를 쓰지 않습니다.
- 커밋하지 않습니다. 하네스가 합니다.

## 끝낼 때
어떤 동작을 테스트했는지 한 줄로 답합니다.
